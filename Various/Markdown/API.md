# Multiline для REAPER

Самостоятельное многострочное поле, выделенное из `ReaCode/filemanager/reacode.lua` и адаптированное к мягким переносам. Исходный редактор не изменён. Есть обычный текстовый режим и живой Markdown в том же поле: заголовки, оформление, задачи, цитаты, код и редактируемые таблицы. Исходный текст, выделение и история общие для обоих режимов.

## Запуск

В REAPER: **Actions → Show action list → ReaScript: Load… → `mrtnz_Markdown.lua` → Run** для Markdown или `mrtnz_Multiline demo.lua` для базового текстового поля.

Оба действия устанавливаются в секцию Main. Установка через ReaPack и пример подключения библиотеки: [README.md](README.md).

Зависимость: [ReaImGui](https://cfillion.ca/reaper_imgui_doc.html), совместимый API `0.9.2.3`, как у исходника. JS_ReaScriptAPI, Python, profiler, `reaper_api.lua` и файловый менеджер для этого поля не требуются.

В базовой демонстрации доступны обычный текст, 20 000 строк, очень длинная строка, undo/redo, wrapping, смена размера шрифта, read-only и два независимых поля. В Markdown-демонстрации — открытие/сохранение `.md`, три темы, форматирование, таблицы и переключение исходника. Возможности, сочетания клавиш и ограничения описаны в [MARKDOWN.md](MARKDOWN.md).

После изменения файлов перезапускайте демонстрацию: уже работающий Lua-скрипт держит загруженные модули в памяти.

## Подключение

Пример для скрипта, лежащего рядом с папкой `Markdown`:

```lua
local script_dir = debug.getinfo(1, 'S').source:match('^@?(.*[\\/])')
local Multiline = dofile(script_dir .. 'Markdown/init.lua')
local im = dofile(reaper.ImGui_GetBuiltinPath() .. '/imgui.lua')('0.9.2.3')
local ctx = im.CreateContext('My text editor')
local field = Multiline.new({
  text = 'Начальный текст',
  wrap = true,
  font_family = 'Consolas',
  font_size = 16,
  on_change = function(editor, edit, action)
    -- editor:get_text(); edit == nil при undo/redo
    -- Сохранение файла/проекта принадлежит вызывающему приложению.
  end,
})

local function loop()
  field:prepare(ctx, im) -- каждый кадр ДО первого ImGui.Begin
  local visible, open = im.Begin(ctx, 'My text editor', true)
  if visible then
    local changed, text = field:render(ctx, '##text', 0, 0)
    -- changed означает изменение текста с предыдущего render, а не фокус.
    im.End(ctx)
  end
  if open then reaper.defer(loop) end
end

reaper.atexit(function() field:dispose() end)
reaper.defer(loop)
```

`prepare` создаёт и прикрепляет шрифты вне активного кадра ImGui. Изменение размера шрифта в обработчике ввода подхватывается следующим `prepare`. У каждого экземпляра своё состояние; для другого ImGui-контекста нужен другой экземпляр. `init.lua` не меняет `package.path` и не публикует глобальные функции/`editor`.

## Управление

| Действие | Поведение |
|---|---|
| Клик / протягивание | Курсор / направленное выделение; автопрокрутка за границей поля |
| Shift + клик / стрелки | Продолжение выделения от исходного якоря |
| Двойной клик / протягивание | Выделение слова / расширение по словам |
| Тройной клик | Весь документ, как в ReaCode; настройка `triple_click = 'line'` переключает на исходную строку |
| Ctrl+A / C / X / V | Выделить всё / копировать / вырезать / вставить |
| Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y | Undo / redo |
| Ctrl + влево/вправо | Переход через непробельный фрагмент и пробелы, как в исходнике |
| Вверх/вниз, PageUp/PageDown | Экранные ряды с сохранением желаемого X |
| Home/End | Начало/конец экранного ряда; Ctrl — всего документа |
| Backspace/Delete + Ctrl | Удаление символа / слова |
| Tab / Shift+Tab | Сдвиг исходных строк; частичное выделение обрабатывается отдельно, как в ReaCode |
| Ctrl + колесо | Размер шрифта, шаг 2; пределы настраиваются |
| Shift + колесо | Горизонтальная прокрутка при выключенных переносах |
| Ctrl+/ | Комментарий, только если задан `comment_prefix`, например `'-- '` |

Нумерации строк и её резервного места нет. Скроллбары появляются при переполнении. Пустые строки, выделенный перевод строки и последняя пустая строка документа имеют свою геометрию.

## API

Все позиции — **байтовые UTF-8-смещения с нуля**, диапазоны — **`[first, last)`**. Позиции внутри многобайтового символа приводятся к его началу. `anchor` и `caret` сохраняют направление выделения.

| Метод | Назначение |
|---|---|
| `Multiline.new(options)` | Новый независимый экземпляр |
| `get_text()` | Исходный текст, без добавленных wrapping-переносов |
| `set_text(text, undoable)` | Заменить документ; по умолчанию очистить историю и перейти в начало; `true` — одна отменяемая операция |
| `insert_text(text, kind)` | Заменить выделение или вставить в курсор; обычный внешний вызов не склеивается с набором |
| `replace_range(a, b, text, kind)` | Одна отменяемая замена диапазона |
| `get_selection()` | `anchor, head`, либо `nil, nil` |
| `get_selected_text()` | Текст выделения |
| `set_selection(anchor, head, affinity)` | Установить направленное выделение; `nil` в anchor снимает его |
| `set_caret(pos, extend, affinity)` | Поставить курсор; `extend=true` сохраняет якорь |
| `select_all()` | Выделить документ, сохранив положение просмотра |
| `get_state()` / `restore_state(state)` | Курсор, якорь, сторона переноса и прокрутка; текст в состояние не входит |
| `undo()` / `redo()` | Восстановить текст, курсор, выделение и прокрутку |
| `delete(direction, word)` | `-1` назад, `1` вперёд; `word=true` — по словам |
| `indent(unindent)` | Отступ / снятие отступа |
| `toggle_comment(prefix)` | Настраиваемый префикс; полная строка и частичный диапазон |
| `find_all(query, options)` | `matches, error, truncated`; элементы `{first, last, line}` |
| `replace_all(query, replacement, options)` | `count, error`; одна запись истории |
| `set_wrap(boolean)` | Переключить переносы |
| `set_read_only(boolean)` | Режим чтения; выделение и копирование остаются доступны, в Markdown ссылки открываются обычным кликом |
| `set_font_size(size)` | Заказать размер шрифта к следующему кадру |
| `set_markdown(boolean)` | Переключить живой Markdown и исходник, сохранив документ и историю; после подключения UI применяется в следующем `prepare` |
| `format(command, value)` | Форматирование Markdown и вставка таблицы; команды перечислены в `MARKDOWN.md` |
| `set_projection(provider)` | Заменить отображение исходных единиц; `nil` возвращает обычный текст |
| `focus()` | Передать фокус полю при следующем render |
| `scroll_to(pos, align)` | Показать исходную позицию, сохранив выделение; `align='start'` помещает её в начало видимой области |
| `prepare(ctx, im)` / `render(ctx, id, w, h)` / `dispose()` | Жизненный цикл виджета |

`affinity` равна `'upstream'` для конца предыдущего ряда и `'downstream'` для начала следующего: на мягком переносе одна исходная позиция имеет два экранных положения. По умолчанию используется downstream. Это не дополнительный символ в документе.

Размеры `render` следуют BeginChild: `0` — доступное место, положительное число — размер, отрицательное — отступ от дальней границы.

Основные настройки: `wrap`, `word_wrap`, `font_family`, `font_size`, `min_font_size`, `max_font_size`, `zoom_step`, `tab_size`, `tab_mode`, `insert_spaces`, `read_only`, `padding`, `overscan`, `selection_rounding`, `triple_click`, `double_click_time`, `comment_prefix`. Цвета: `background`, `text_color`, `selection_color`, `inactive_selection_color`, `caret_color`, `current_row_color`; функция `color_for_range(editor, first, last, role)` может переопределять цвет.

`tab_mode='line'` сохраняет поведение исходника без выделения. `tab_mode='insert'` вставляет табуляцию в курсор. `insert_spaces=true` вставляет пробелы вместо `\t`. Отступы всегда относятся к исходным строкам, а не к экранным переносам.

Опции поиска: `case_sensitive`, `whole_word`, `in_selection`, `first`, `last`, `use_pattern`, `limit`. Обычный поиск буквальный. Регистронезависимое сопоставление использует ASCII-правила Lua; точный поиск кириллицы работает. `use_pattern` включает именно Lua patterns с их собственными правилами регистра, а не PCRE. Пустые совпадения продвигают поиск. По умолчанию patterns ограничены диапазоном в 15 000 байт, выдача — 10 000 совпадений; лимиты настраиваются через `pattern_byte_limit` и `limit`. При усечённой выдаче `replace_all` возвращает ошибку и ничего не меняет. Текст замены буквальный, без подстановки captures.

`read_only` блокирует редактирование, undo и redo; программный `set_text(text)` предназначен для загрузки документа и остаётся доступным.

## Большие документы

Исходные строки индексируются независимо от визуальных. На экране обрабатываются видимые ряды с небольшим буфером. Поиск исходной строки и экранного ряда — двоичный/Fenwick; hit-test использует контрольные точки через 128 единиц и короткий локальный проход вместо измерения всех префиксов строки.

Длинные строки размечаются порциями: `layout_budget=12000` единиц и мягкий временной бюджет `layout_seconds=0.004`. Во время первичной разметки общая высота приблизительная; ещё не готовые ряды показывают `...`, клик по ним не подставляет выдуманную позицию. Привязка просмотра к исходному тексту сохраняется при уточнении высоты и смене ширины/шрифта. Редактирование конца большой строки сохраняет уже рассчитанный префикс; пересчитывается хвост с запасом для переноса слова.

Изменение ширины не пересоздаёт индекс всех строк. Последние количества рядов сохраняются до порционного уточнения; сначала рассчитывается исходная позиция просмотра и область вокруг неё, затем фоновые строки. Это предотвращает скачок высоты к новой приблизительной оценке на каждом движении границы окна. При последовательных сужениях и расширениях сохраняется один исходный якорь просмотра; прокрутка или навигация задаёт новый. Без wrapping изменение ширины вообще не сбрасывает геометрию текста.

В renderer не передаётся мегабайтная строка: текст отправляется короткими видимыми участками, включая горизонтальный режим. `max_draw_units=32768` ограничивает патологический объём рисования за кадр. Ширины шрифта кэшируются с учётом смены размера; усреднение измерений уменьшает накопление пиксельного округления CalcTextSize.

История по умолчанию ограничена 1000 транзакциями и 16 MiB вставленных/удалённых данных. Последняя большая операция сохраняется даже при превышении этого лимита. Снимки всего документа на каждую букву не создаются; сама замена в Lua-строке всё ещё имеет линейную стоимость по размеру документа.

## Markdown и проекции

Единый источник истины — `document.text`. Layout получает из projection отображаемую единицу вместе с её исходным диапазоном. Ширины, hit-test, выделение и курсор используют эту же раскладку. Markdown подключён через этот контракт в том же поле; отдельного документа с результатом рендера нет.

Контракт: `provider.next_unit(line, offset)` возвращает `next_offset, display_text, role`. По умолчанию это один UTF-8-символ; табуляция имеет свой advance. В обычном текстовом режиме `color_for_range` принимает исходный диапазон и роль, а `set_projection(provider)` меняет проекцию. В Markdown проекцией и цветами управляют его parser/layout/theme; `set_projection` в этом режиме запрещён.

Живой режим использует переменную высоту заголовков и блоков, раскрывает разметку активной строки/ячейки и сохраняет геометрию при протягивании выделения. Подробности и границы поддержки — в [MARKDOWN.md](MARKDOWN.md). Навигация работает по кодовым точкам UTF-8; полная Unicode-сегментация графем, bidi и настройка окна IME пока не реализованы.

История переноса и сознательные изменения поведения перечислены в `PORTING_MAP.md`. Проверочные скрипты и Python-зависимости вынесены из проекта по просьбе владельца; они не нужны для работы поля.
