# Как сравнить правку с реальным звуком

Нужны три состояния одного фрагмента: исходник, правка до склейки и звук после
склейки. Белая линия после правок подписана `White: target prediction` — это расчётная цель. Повторный Analyze исходного
take читает звук до FX, поэтому для проверки результата нужна склеенная копия.

## Один воспроизводимый тест

1. Создай отдельный тестовый проект и сохрани его. Возьми исходный вокальный
   фрагмент длиной 3–5 секунд, оставив по возможности по 0,3–0,5 секунды вокруг
   проблемного места. Не меняй его скорость и границы между сравнениями.
   Для первого теста оставь на дорожке и мастере пустые FX-цепочки.
   Короткий звук около 0,5 с тоже подходит для первого случая. Сохраняй один
   и тот же start/end у A, B и C: иначе придётся отдельно устанавливать,
   совпадают ли правка, обрезка и печать. В 0.9.7 алгоритм ReaPitch можно
   выбрать в редакторе; фактический выбор попадёт в экспорт B.
2. Это **A — исходник**. Analyze → дождаться окончания → **Export case**.
   В консоли REAPER появится путь к папке. Скопируй его в заметку как «A».
3. Сделай копию A на другой дорожке с тем же началом и длиной. Это **B — правка**.
   Внеси только проверяемую правку: например Flatten 100% на одной ноте.
   Дождись применения. Режим должен быть Edited: если кнопка показывает
   **Original**, эффект сейчас включён; если **Edited** — сейчас обход,
   нажми её, чтобы вернуть эффект. Нажми **Export case**, сохрани путь как «B».
4. Сделай копию B на третьей дорожке. Это **C — печать**. Выдели только C и
   выполни **Item: Glue items, ignoring time selection**. Используй одну эту
   команду; не добавляй к этому проходу Apply track/take FX и отдельный render.
   B оставь несклеенным, чтобы сохранить редактируемую огибающую.
5. У C проверь Take FX: второй активной копии **Vocaligner Pitch** быть не должно.
   Выдели только C → **Analyze** → дождаться окончания → **Export case**.
   Ничего не подтягивай и не выпрямляй после этого анализа. Сохрани путь как «C».
6. Сохрани проект. Передай три пути A/B/C и путь к RPP. Файлы звука оставь на
   месте: выгрузка содержит их пути, но не копирует WAV. На этом компьютере
   этого достаточно для проверки. Для передачи на другой компьютер понадобятся
   также исходный WAV и WAV, созданный Glue.

После Glue редактор 0.12.0 отбрасывает удалённый указатель айтема. Если до
Analyze показано сообщение об удалённом ReaPitch, нажми Analyze на копии C: она
должна получить свежий анализ без повторения уже впечатанных правок. Если
ошибка остаётся после Analyze, сохрани проект и Copy report.

Для прослушивания включай только одну из A/B/C, чтобы не складывать копии.
Для следующего теста снова копируй A. Не используй уже склеенный C как исходник.
Сначала достаточно одного Flatten и одного Draw; потом можно добавить
обычный сдвиг +1 полутон как контроль и Vibrato около 5 Гц.
Для отдельного Vibrato-теста оставь Formant = 0 и остальные правки сброшенными.
Сочетание сильного Vibrato и Formant тоже полезно, но это отдельный случай.

## Что сохраняет Export case

Папки создаются в `REAPER resource path/Data/VocalignerPitchCases/`.
Путь печатается в консоль; каждая выгрузка получает отдельную папку.

- `case.json`: все параметры нот и точки Draw, геометрия take, пути к звуку,
  реальные параметры/огибающие и алгоритм ReaPitch, сведения о FX и аудиоустройстве.
- `analysis.csv`: измеренный входной F0, confidence и уровень каждого кадра.
- `target.csv`: исходный F0, расчётная цель и поправка на сетке 5 мс.
- `item.chunk`: состояние айтема с настройками плагина.
- `report.txt`: обычный полный отчёт.
- `COMPLETE.txt`: выгрузка завершилась. Папка без него может быть неполной.

Export case читает состояние и записывает эти файлы. Он не меняет айтем,
не добавляет Undo, не склеивает и не рендерит звук. Если экспорт прерван,
повторное нажатие создаёт новую папку.

## Как будут сравниваться результаты

Сначала сверяется расчётная поправка B с прочитанными из REAPER точками
огибающей. Затем цель B сравнивается с анализом C на одинаковом времени.
Отдельный исследовательский инструмент `audit_case_audio.py` читает WAV, строит F0 через Praat и спектрограмму. Он уже проверен на сигнале с известным сдвигом; твоё аудио ещё не проверено. Независимый измеритель тоже может ошибаться. Смещение по времени нельзя
молча подбирать так, чтобы графики выглядели похожими.

SwiftF0 измеряет высоту каждые 16 мс и использует временной контекст. Это не
идеальный измеритель быстрых Draw-зубцов. В контрольном тесте без ReaPitch
обычное вибрато 5 Гц измерялось с 95-м процентилем ошибки около 5 центов,
а рисунок 25 Гц с резкими краями — около 52 центов. Это синтетический пример,
не измерение твоего вокала и не оправдание расхождений Flatten.

Линия без блока тоже сохраняется в выгрузке. Видимость линии и выделение
ноты используют разные правила: наличие уверенного кадра ещё не означает,
что найден устойчивый нотный участок. Без его данных пороги не меняем.

Справка: [REAPER AudioAccessor читает pre-FX](https://www.reaper.fm/sdk/reascript/reascripthelp.html#GetAudioAccessorSamples),
[руководство REAPER](https://www.reaper.fm/userguide.php).
