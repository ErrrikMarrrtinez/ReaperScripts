# Связь между нотами v2: окно из F0 и постоянный объект

Статус: спецификация после 0.11.0 (2026-10-02), не внедрено. Исправляет три вещи в текущем `link.lua` / `ui.lua`: окно связи лежит в паузе, а не на глиссандо; оранжевое остаётся подсветкой белой линии, а не объектом между блоками; у связи нет множителя доверия. Остальное из 0.11.0 (Hermite, Shape/Bias/Settle/Mix/Overshoot, захват без смены инструмента, v4) сохраняется.

## 1. Почему текущее окно не работает

[link.lua:7-12](link.lua#L7-L12): окно центрировано на середине промежутка, половина ширины ≤ 150 мс и ≤ 45 % каждой ноты. Блоки обрезаны DP по стабильному ядру, глиссандо остаётся белыми хвостами снаружи. При промежутке 150–300 мс окно целиком в паузе: Shape и Bias формируют кривую там, где нет голоса, а хвосты нот не трогаются. На экране видно только обрывок onset-глиссандо, который попал в окно, и grip на его нижнем конце.

[link.lua:19-21](link.lua#L19-L21): концы берутся из `Expression.sample`, которая не смотрит на confidence. В кейсе `20261002-153626` между нотами 2 и 3 кадры 0.450–0.480 с имеют pitch 69–84 MIDI при confidence 0. Если конец окна попадает туда, целевая прямая стартует с мусора, а `Link.at` без доверия пишет до ±24 st поправки на дыхание.

## 2. Окно связи из F0

Для пары `(a, b)` с `can_link` (промежуток ≤ 300 мс). Все величины из исходного анализа `data.frames`, не из правок: глиссандо живёт в источнике.

```
confident(f)  = f.confidence >= .5 and (f.level_db or -20) > -60
band(n)       = clamp(p80(|f.pitch - n.center|) по confident кадрам в [n.start+m, n.finish-m]), .5, 1.5)
                m = min(.04, .12*(n.finish-n.start)); если кадров < 3 → band = .6
mid_a = a.start + .5*(a.finish-a.start);  mid_b = b.start + .5*(b.finish-b.start)

t_dep = время последнего confident кадра в [mid_a, b.start]
        с |pitch - a.center| <= band(a)               -- голос ещё «на ноте A»
t_arr = время первого confident кадра в [a.finish, mid_b]
        с |pitch - b.center| <= band(b)               -- голос уже «на ноте B»
если t_dep нет → t_dep = a.finish;  если t_arr нет → t_arr = b.start
если t_arr <= t_dep → t_dep, t_arr = t_dep, t_dep + hop   -- мгновенная смена, окно в один кадр

auto_lo, auto_hi = t_dep, t_arr
```

Пользовательские параметры применяются к автоокну, а не к геометрии промежутка:

```
c      = (auto_lo+auto_hi)/2 + bias * (auto_hi-auto_lo)/2
half   = scale * (auto_hi-auto_lo)/2            -- scale ∈ [.25, 2], по умолчанию 1
lo, hi = clamp(c-half, mid_a, b.start+hop), clamp(c+half, a.finish-hop, mid_b)
```

Соседние связи не пересекаются: правая связь ноты `b` начинается не раньше `mid_b`, левая заканчивается не позже `mid_b`.

Детекция стоит ≤ (0.45·длина ноты + промежуток)/16 мс кадров, обычно 10–60 чтений. Результат мемоизируется по ключу `(frames, a.start, a.finish, a.center, b.start, b.finish, b.center)` в `data._link_windows`; инвалидация вместе с `_contour_runs` (та же проверка `frames` и их количества). Внутри одного прохода вычислителя контекст `context[b]` уже кэширует подготовку.

## 3. Концы и форма

Концы только из доверенных кадров. Добавить в `expression.lua`:

```
Expression.trusted(data, t, direction)  -- ближайший confident кадр в сторону direction, не дальше 32 мс
  → pitch, trend, t_frame  или nil
```

```
pa, ta = trusted(data, lo, -1);  pb, tb = trusted(data, hi, +1)
если pa или pb нет → связь акустически неактивна (mix считается 0), визуально рисуется пунктиром (п. 4)
left  = trend_a(ta) + value(a, ta)      -- линия ноты, не мгновенный F0
right = trend_b(tb) + value(b, tb)
ma, mb = наклон trend ± один кадр, ограничение как сейчас (длина (α,β) ≤ 3)
```

Форма. Сейчас Shape переназначает параметр Hermite `v = u^s/(u^s+(1−u)^s)`, из-за чего при `s ≠ 1` производная на концах не совпадает с наклоном ноты. Разделить значение и наклоны:

```
u = (t-lo)/(hi-lo);  v = u^s/(u^s+(1-u)^s);  g = v*v*v*(v*(6v-15)+10)      -- квинтик, g'(0)=g'(1)=0
b1 = u^3 - 2u^2 + u;  b2 = u^3 - u^2                                      -- базис наклонов Hermite
core   = left + (right-left)*g + h*ma*b1 + h*mb*b2                        -- C1 на обоих концах при любом s
compact = 16*u^2*(1-u)^2
residual = raw - (pa + (pb-pa)*u)
target = core + (1-settle)*residual*compact + overshoot*compact*sin(2πu)
```

Применение с доверием:

```
support = Draw.support(data, t)            -- перенести в Expression.support, Draw и Link используют одну функцию
join    = smooth(u/.15) * smooth((1-u)/.15)
result  = base + (target - raw - base) * mix * join * support
```

При `support = 0` (пауза, согласная, скачок ≥ 3.5 st) связь не пишет поправку. Это восстанавливает защиту, которая в v3 обеспечивалась множителем `trust` в [curve.lua:98](curve.lua#L98).

## 4. Постоянный объект на экране

Заменить блок [ui.lua:340-387](ui.lua#L340-L387). Для каждой пары с `can_link`, попадающей в экран, независимо от выделения и инструмента (кроме Bypass):

1. Окно `lo, hi` из п. 2, с текущими параметрами связи или автозначениями.
2. Точки с шагом ≈ 1.5 px по времени от `lo` до `hi`. Где `Contour.sample` даёт значение — `pitch = raw + Curve.at(...)`, рисуется сплошной линией. Где значения нет — пунктирная направляющая между последней и следующей известной точкой; в полностью неозвученной паузе это пунктир от `left` к `right` по той же формуле `core`.
3. Цвет: `0xF5AB5540` для неактивной связи (mix = 0, показывает путь исходного глиссандо), `0xF5AB55C0` для активной, `0xFFD582FF` при наведении или drag. Толщина 2.5 / 3.2.
4. Grip: «таблетка» 14×6 px в `t = (lo+hi)/2`, `y` на нарисованной линии в этой точке (сплошной или пунктирной). На концах окна — засечки 1×6 px, чтобы ширина была видна.
5. Попадание: ±8 px вдоль всей линии и ±10/8 px у grip. Жесты без изменений: вертикально Shape, горизонтально Bias, Shift Width (теперь scale), Alt Settle, двойной клик сброс; в Curve/Draw только по grip с Ctrl. Инструмент не переключается.
6. Бейдж: `lo…hi мс | Shape | Bias | Settle`, значения окна в миллисекундах реального окна.
7. Белая линия внутри окна не рисуется второй раз: сплошная оранжевая её замещает, как сейчас.

Стоимость: один дополнительный проход вычислителя на ширину окна в пикселях; для 10 видимых связей по 60 px это ≈ 600 вызовов, в кэше `display` уже есть большинство точек на тех же `t`. Переиспользовать `display._samples`, дорисовывать только пунктир.

## 5. Данные и совместимость

```
link = {version=2, owner=id, scale=1, bias=0, shape=1, mix=0, settle=1, overshoot=0}
```

- Старые `link.version=1` с `width` в секундах продолжают считаться старым `Link.window` до первого редактирования этой связи. При редактировании: `scale = clamp(width / (auto_hi-auto_lo), .25, 2)`, версия 2. Сохранённые огибающие при открытии не меняются.
- `Store.read`: диапазоны `scale .25…2`, `bias −.75….75`, `shape .25…4`, `mix 0…1`, `settle 0…1`, `overshoot −2…2`, `version 1|2`.
- `Notes.voice_fields`/`same_curve` уже сравнивают `link`; добавить `version` и `scale` в сравнение таблиц.
- `changed_ranges` ([notes.lua:50-71](notes.lua#L50-L71)) помечает соседние ноты целиком, окно связи внутрь этого диапазона попадает всегда.
- Split: окно пересчитывается из новой геометрии; `owner` остаётся, внутренняя граница половинок связь не получает. Bounds меняет `mid_a/mid_b` и, значит, зажимы окна: это ожидаемо и видно на экране.
- Числовые контролы Transition: Width показывать как `%` от автоокна (25–200) и рядом фактические мс.
- `curve_version` остаётся 4; новое поведение включается только версией самой связи.

## 6. Проверки на кейсе `20261002-153626-a00df3a8`

Исходный анализ без правок, 8 нот. Ожидаемые окна по `analysis.csv` (уточнить при реализации, допуск ±1 кадр):

| Пара | Геометрия | Ожидаемое автоокно | Что проверяет |
| --- | --- | --- | --- |
| 2 → 3 | промежуток 112 мс, внутри кадры 69–84 MIDI при confidence 0 | `t_dep ≈ 0.400`, `t_arr ≈ 0.545` | концы не на мусорных кадрах; `support = 0` на 0.42–0.53; поправка там ровно 0 при mix 1 |
| 3 → 4 | касание на 0.624, 60.4 → 63.25 | `lo ≈ 0.60–0.61`, `hi ≈ 0.64` | окно покрывает глиссандо внутри блоков; Shape 0.25 и 4 меняют наклон в 0.61–0.64, значения в 0.56 и 0.69 неизменны |
| 4 → 5 | промежуток 96 мс | концы на последнем/первом confident кадрах | непрерывность C0 ≤ 0.5 ct и наклон ±10 % на `lo`/`hi` |
| 5 → 6 | промежуток 160 мс, тихий хвост | то же | хвост с trust < 1 не тает: поправка удерживается до `support = 0` |

Общие утверждения для автотеста:

1. Для всех пар `lo` и `hi` лежат на кадрах с confidence ≥ 0.5 либо на границах нот; никогда на кадре с confidence < 0.5.
2. При `mix = 0` результат побитово равен вычислителю без связи.
3. При `mix = 1` максимум |поправки| на кадрах с `support = 0` равен 0. Тот же тест на коде 0.11.0 должен провалиться для пары 2 → 3: это фиксирует дефект п. 1.
4. Для `shape ∈ {.25, 1, 4}` численная производная цели на `lo` и `hi` совпадает с наклоном линии ноты в пределах 10 %.
5. Огибающая против вычислителя ≤ 0.3 ct на сетке 0.1 мс при активной связи с Overshoot 50 ct.
6. Окно и объект не зависят от `e.selected` и `e.tool`; grip лежит внутри `[lo, hi]`; клик по связи не меняет `e.tool`.
7. Старый проект с `link.version = 1`: открытие не меняет огибающую; первое редактирование переводит в v2 одной Undo-транзакцией.
