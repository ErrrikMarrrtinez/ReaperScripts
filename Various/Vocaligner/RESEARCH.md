## Почему старый вариант особенно ломается в первый раз

### 1. Подтверждённая гонка публикации gmem

`main_alignment.py:342–369`, функция `write_anchors_to_gmem`, делает следующее:

1. Записывает `gmem[0] = 2`, то есть «оба массива готовы».
2. Записывает длину и значения референса.
3. Записывает длину даба.
4. Только после этого записывает значения даба.

Каждая запись — отдельный RPC-вызов. Сервер обслуживает их через `reaper.defer`. Между ними работает Lua-получатель, который проверяет флаг и равенство двух длин. Как только записана длина даба, обе длины уже равны, **но данные даба ещё не готовы**.

Это воспроизведено автономно: из Python AST извлечена только исходная функция записи, вместо RPC подставлена память с имитацией чтения после каждой записи. Для референса `[0.1, 0.4, 0.9]` и даба `[0.12, 0.43, 0.94]` получатель успевает принять `[0.1, 0.4, 0.9]` и `[0, 0, 0]`. Соединений с REAPER эта проверка не создаёт.

При повторном запуске в памяти могут оставаться прошлые значения. Поэтому симптом «первый раз плохо, второй лучше» согласуется с этой гонкой. Но без конкретного проекта нельзя доказать, что весь слышимый дефект вызван только ею: ниже есть отдельные ошибки координат и старых маркеров. В старую связку исправления не вносились по согласованному направлению работы; в новой gmem/RPC отсутствуют.

### 2. Анализируется исходный файл целиком

В `preprocess_audio`, строка 95, вызывается `librosa.load(path, sr=None, mono=True)`. В обработку не передаются начало в источнике, слышимая длина айтема, play rate или существующая карта растяжения. У двух обрезанных айтемов сравниваются совсем другие границы, чем видит пользователь.

В конце полные длительности файлов принудительно становятся конечными опорами. Lua затем трактует эти времена как времена внутри текущих айтемов. Glue меняет источник и обнуляет часть различий координат, поэтому способен скрыть эту ошибку, но не исправляет протокол.

### 3. Один результат применяется ко всем дабам

Python сортирует выделенные айтемы по позиции и анализирует только `items[0]` и `items[1]`. Lua позже заново читает выделение в собственном порядке, пропускает первый элемент и применяет одну пару массивов ко всем остальным. Референс может оказаться другим, а третий даб получает карту второго. Идентификатора запроса и привязки результата к take GUID нет.

### 4. Настройки и маркеры применяются без проверки

Lua добавляет новые маркеры поверх существующих; результаты `SetTakeStretchMarker` не проверяются. Попытка установить `D_PLAYRATE` через **item** API адресована неверному владельцу свойства: это свойство **take**. Затем глобальная замена `PLAYRATE` в item chunk затрагивает совпадающие строки всех тейков этого айтема.

В новой реализации используются свойства конкретного take: `I_PITCHMODE`, `I_STRETCHFLAGS` и `F_STRETCHFADESIZE`. Выбраны tonal и 7.5 ms, как в исходном chunk. Настройка уменьшает риск артефактов, но не гарантирует отсутствие щелчков при любой карте растяжения. Значения и сигнатуры функций сверены с [официальным ReaScript API](https://www.reaper.fm/sdk/reascript/reascripthelp.html#SetMediaItemTakeInfo_Value).

## Что реально делает Python

В активном пути **нет PyTorch и нейросетевой модели**. Используются NumPy, librosa, SciPy, scikit-learn и локальный RPC. Наличие torch/CREPE и других пакетов в окружении не означает их участие в выравнивании.

Последовательность:

1. Загрузка, перевод в mono, ресемплинг в 44.1 kHz, нормализация пика. Опциональный HPSS по конфигу выключен.
2. FFT 2048, шаг 512: примерно 46.4 ms окна и 11.6 ms между кадрами.
3. MFCC 13, chroma 12, onset strength / spectral flux и RMS.
4. Независимая стандартизация каждой группы для каждой записи, взвешенное объединение и косинусное расстояние.
5. DTW, привязка к onset-кандидатам, медианный фильтр и сокращение опор через RDP.

MFCC описывают сглаженную спектральную форму: энергия mel-фильтров → логарифм → DCT. Они полезны для различения фонетических участков, но не являются распознаванием слов. Chroma сворачивает высоты по 12 классам и может помогать унисонным партиям, одновременно мешая гармониям. Flux ищет изменения спектра, RMS — огибающую энергии. Их ошибки различны, поэтому сочетание информативнее одного RMS. Определение MFCC сверено с установленной реализацией librosa 0.10.1; справка — [librosa MFCC](https://librosa.org/doc/0.10.1/generated/librosa.feature.mfcc.html).

### Дополнительные проблемы алгоритма

- В `compute_dtw_path:152–163` доля полосы `0.15` переводится в число кадров, а затем передаётся в `band_rad`, который ждёт **долю**. Например, для 1000 кадров получается 150 вместо 0.15. Ограничение фактически исчезает; плотная матрица остаётся дорогой. Это сверено с установленным `librosa/sequence.py` и [описанием DTW](https://librosa.org/doc/main/generated/librosa.sequence.dtw.html).
- Взвешивание стандартизированных групп перед общим cosine не равно линейному смешиванию их расстояний: влияют квадраты весов и количество компонентов. Настройки `0.35/0.25/0.25/0.15` не дают этих долей в итоговом качестве сопоставления.
- Каждый вызов MFCC/chroma/onset/RMS повторяет часть спектральной работы. Один STFT может обслуживать несколько признаков.
- Пользовательский `symmetric2` отдаёт составным шагам меньшую цену без полного учёта пропущенных кадров. Это может поощрять обход атак, а не только нужную деформацию времени.
- `subseq=False` заставляет сопоставлять полные границы даже при разном обрезании.
- Медианный фильтр применяется к абсолютным временам, а не к отклонениям от исходного тайминга; дополнение нулями плохо для краёв.
- В `select_anchors:277–340` список сначала заполняется onset-опорами, после чего сканирование плотного пути начинается с ограничением по последнему onset. Кандидаты до него могут не попасть в промежуточный набор.
- Параметры refinement читаются из `[AnchorRefinement]`, а INI содержит их в `[Anchors]`. Параметры связи читаются из `[Communication]`, но файл содержит `[GMEM]`. Работают fallback-значения, а не все видимые настройки.
- Нет единой проверки минимального расстояния, монотонности и локального отношения скоростей для всех сегментов, включая края.

## MPL и VoxAlign: что полезно, что не переносилось

**MPL 3.11.** Полезны реальная работа с REAPER-координатами, штатные настройки stretch и работа с атаками. Текущая версия строит CDOE либо RMS-огибающую и локально ищет растяжение между опорными участками. CDOE использует короткий FFT; RMS-ветка сворачивает несколько полос в скаляр. Это не эквивалент сопоставлению богатых спектральных векторов. Основной track-accessor может включать соседние айтемы/микс; в новом проекте используется только take-accessor. Старый INI и современный ExtState нельзя считать одним конфигом. Также замечены подозрительное выражение `item_pos+item_end` в проверке границы, локальные копии и неоднородные преобразования крайних маркеров — не основание копировать блок целиком.

**VoxAlign, исследованная ревизия.** Полезны несколько полос, поиск грубого сдвига, многоуровневый DTW, попытка выделить дыхание и распределение части работы по кадрам GUI. При этом чтение/фильтрация/корреляции остаются тяжёлыми синхронными фазами; fallback с take на track способен анализировать другую смесь. Пирамида прореживает кадры без усреднения, локальный stretch не гарантируется глобальной полосой, а недостижимый конец DTW не всегда превращается в отказ. Проверки краёв неполные; позиция нового маркера не везде учитывает play rate. Микропривязка по форме волны ненадёжна при разных голосах/высотах. Использованы идеи, а не копия этих процедур. [Исходник VoxAlign](https://github.com/AcrosonusMastering/VOXALIGN/blob/main/Script/VOXALIGN_V1.lua).

Эти замечания относятся к прочитанным файлам и не являются сравнением качества на общем наборе записей. Новый код написан независимо; чужие исходники и их зависимости в проект не включены.

## Алгоритм новой версии

### Анализ

Читаются короткие участки именно захваченного take. В 0.1.x использовались 16 kHz, FFT 512 и шаг 160. В 0.2.0 — 32 kHz, FFT 1024, шаг 320: сохранены окно 32 ms и шаг 10 ms, добавлена информация выше 8 kHz для деэссера. Один спектр обслуживает mel/MFCC, spectral shape, chroma, атаки и дополнительные энергетические показатели. Каналы объединяются по мощности, а не сложением противофазных сэмплов. Стандартизация оценивается на активной части записи; группы расстояний нормированы по размерности. Короткая фраза среди длинной тишины не должна исчезать из-за 95-го процентиля.

Chroma получает меньший вес для речи и выключается в профиле разных голосов/гармоний. Дыхание оценивается по спектру, относительной громкости и длительности; это ограниченная эвристика, которая может ошибаться на согласных.

### Сопоставление

Грубый уровень усредняет четыре кадра. Подробный ищет внутри коридора вокруг грубого пути, с расширенной повторной попыткой при высокой стоимости. Внешняя граница задаётся в **секундах смещения относительно проекта**, а не ошибочно пересчитанных долях матрицы.

Более короткая активная последовательность ищется внутри длинной со свободными префиксом/суффиксом. Обе записи с разным непересекающимся материалом на обоих концах — более сложный случай, чем такое вложение; качество там не гарантируется. Путь обязан быть достижимым. Составные шаги учитывают промежуточную стоимость. Тишина с одной стороны не скрывается из оценки качества; недостаточная поддержка отключает результат по умолчанию.

Хранятся три строки стоимости и упакованные байты направлений внутри полосы. Это ограниченный по полосе алгоритм, **не** обещание линейной памяти для произвольного полного DTW. Повторное сопоставление использует кэш признаков и уровней; интерфейс получает управление в контрольных точках. Бюджет кадра мягкий: отдельный нативный вызов или сортировку Lua нельзя прервать посередине.

Обоснование свободных концов: [AudioLabs — subsequence DTW](https://www.audiolabs-erlangen.de/resources/MIR/FMP/C7/C7S2_SubsequenceDTW.html). Ограничения и варианты шагов: [AudioLabs — DTW variants](https://www.audiolabs-erlangen.de/resources/MIR/FMP/C3/C3S2_DTWvariants.html). Многоуровневое аудиосопоставление: [Sync Toolbox](https://github.com/groupmm/synctoolbox). Приближённый FastDTW не выбирался автоматически как «всегда быстрее»: [сравнение FastDTW и DTW](https://arxiv.org/abs/2003.11246).

### Из пути в маркеры

Путь ещё не является хорошей картой растяжения. Сначала отбрасываются слабые соответствия и сравнивается исходное положение: почти совпадающий даб не должен двигаться ради мизерного выигрыша метрики. Сглаживается смещение. Затем применяются tolerance и strength, добавляются края, ограничиваются локальные скорости, сохраняются заметные атаки и сокращается карта. После сокращения проверяются все сегменты ещё раз.

Для захваченного айтема без маркеров, где `t` — время от его начала:

```text
source_time(t) = original_offset + original_rate * t
new_marker_position = (target_project_time - new_item_position) * original_rate
```

При существующей допустимой карте source_time вычисляется кусочно-линейно. Первая и последняя source-координаты сохраняются. Новая позиция/длина следуют из target-координат этих краёв. Поэтому тишина и обрезание не требуют растянуть первый отрезок до условного нуля референса. Сопоставление не переносится между разными дабами.

### Применение и восстановление

Перед изменением проверяется вся выбранная группа: проект, живые указатели, состояние референса и каждого даба. Известные состояния собственных Apply и оригинал после Undo допустимы, чужая правка — повод перезахватить айтемы. У каждой новой опоры проверяются возвращённый индекс и фактические координаты. При ошибке восстанавливается вся группа, включая уже обработанные айтемы и настройки take. Снимки существуют только в сессии; постоянный откат остаётся в истории REAPER.

## Что проверено и что ещё неизвестно

### Исправление 0.1.1 по первому отчёту пользователя

В REAPER 7.73/x64 чтение референса завершилось возвратом `nil` из `GetAudioAccessorSamples`, после чего строка `result < 0` вызвала исключение. Предыдущая API-модель всегда возвращала документированное число и не покрывала этот случай. Буфер до падения не был записан в отчёт, поэтому неизвестно, были ли в нём сэмплы.

Теперь создание нативных массивов, чтение/копирование буфера и FFT выполняются из основного deferred-цикла через запрос coroutine. Числовой отрицательный статус остаётся ошибкой, нулевой — пустым блоком; при `nil` проверяются реальные значения буфера. Некорректные числа отклоняются. Если все вызовы вернули `nil` и весь звук остался нулевым, анализ останавливается с отдельной диагностикой. Отчёт сохраняет границы accessor, параметры последнего чтения, количество nil/пустых ответов, непустых блоков и пик.

Автономно проверены nil с заполненным буфером, nil без данных, отрицательный/нулевой статус, NaN в буфере, исключение чтения, освобождение accessor и исполнение чтения вне coroutine. Добавлен отдельный сценарий остановки анализа референса и сохранения ошибки при последующих информационных сообщениях. Следующий пользовательский прогон подтвердил чтение в реальном хосте для указанной пары; причина исходного nil отдельно не доказана.

Интерфейс упрощён: свёрнутые настройки, две полосы, переключение исходного/выровненного даба, Copy report рядом с Analyze и постоянное сообщение ошибки сверху. Его новый внешний вид проверяется пользователем, без самостоятельного запуска REAPER.

### Исправление 0.1.2: недостижимая граница DTW

В отчёте пользователя от 2026-09-29 17:37:50 версия 0.1.1 прочитала оба моно айтема с rate 1: референс — 2207 кадров, 46 непустых чтений, пик 0.74252099; даб — 2306 кадров, 49 непустых чтений, пик 0.90753226. Все статусы чтения равны 1. Волны появились, но грубый поиск не смог завершить путь.

Воспроизведена ошибка границ: при усреднении по четыре кадра последний блок из 1–3 кадров получает время вне номинальной сетки 40 ms. Перевод временной границы в индекс через floor исключал последний столбец референса. Если референс был более короткой последовательностью, обязательная конечная точка становилась недостижимой независимо от качества совпадения. Контрольные длины референса 45, 46 и 47 кадров падали до исправления, а 44 проходила.

Границы теперь находятся двоичным поиском по фактическим временам кадров. Все четыре длины, обратное направление сопоставления и пример с количеством кадров и позициями из пользовательского отчёта проходят. Это проверка геометрии с искусственными признаками, а не повторный анализ пользовательской записи. Полностью разнесённые за пределы диапазона записи по-прежнему отклоняются. Если подробный проход не может пройти внутри коридора грубого пути, он повторяется в исходном диапазоне пользователя; допустимое смещение не увеличивается.

В диагностике добавлены активные и грубые диапазоны кадров, а ошибка недостижимости содержит этап и времена обеих последовательностей. При нуле результатов интерфейс больше не предлагает Apply. Завершение анализа и качество выравнивания на этой реальной паре предстоит проверить пользователю в версии 0.1.2.

### Версия 0.2.0: плавность, Amount и очистка вокала

Пользовательский отчёт 0.1.2 от 17:48 подтвердил Analyze/Apply для четырёх реальных моно дабов, в том числе обрезанных с source offset. Пользователь положительно оценил звук. Это подтверждает работоспособность той версии на этих записях, но не сравнительное превосходство над другими продуктами. У близкого даба отмечены 122 маркера при максимальном смещении 30 ms; у трёх других встречались оба предела локального stretch. Это мотивировало следующую доработку.

- `timing.lua` сглаживает смещения локальной взвешенной линейной регрессией. Для небольших смещений нужен устойчивый локальный выигрыш относительно исходного положения. Слабые соответствия получают меньший вес. Жёсткие ограничения скоростей проверяются после сокращения карты.
- Полная карта вычисляется независимо от Strength. Amount интерполирует target-времена с исходными, сохраняя набор source-опор; выпуклая смесь монотонных карт не пересекает маркеры. Сохраняются также узлы исходной линейной карты. Ноль восстанавливает оригинальные маркеры/тайминг, отдельно включённая очистка остаётся. Apply on release включается фактически только после первого явного Apply, одна операция Undo на отпускание.
- Изучены оба приложенных скрипта: Lua управляет огибающей параметра Soothe на дорожке, EEL строит огибающую громкости take по high-pass детектору, порогу, проценту компрессии, pre-open и интервальному измерению. В EEL параметры пересчитываются по сэмплам и временно меняется playrate для чтения. Новый код написан независимо, без копирования их GUI, Soothe, SWS и временной смены скорости.
- Один спектральный проход сохраняет мощность в полосах по 500 Hz. При изменении cutoff применяется вес, приближающий высокочастотный детектор второго порядка; это не точное воспроизведение временного IIR-фильтра из EEL. Кадровый шаг 10 ms также отличается от его 1 ms огибающей. Сохранены основные ручки threshold / frequency / compression; добавлены предел ослабления и мягкий release.
- Дыхание определяется как тихий продолжительный шумовой участок с низкой долей низких частот; сильные сибилянты уменьшают его оценку. Длительность отсеивает часть коротких согласных. Это эвристика без нейросетевой модели; её точность на реальных дыханиях пока неизвестна. Кандидаты можно исключить правой кнопкой на волне. Ослабление обеих секций выключено при запуске.
- `envelope.lua` читает существующую volume envelope, использует нативную оценку кривой и scaling mode, умножает исходный gain на ослабление и переносит координаты через ту же карту, что и звук. Сэмплирование исходной кривой — 10 ms плюс исходные точки/узлы warp; после упрощения допускается ошибка интерполяции 0.1% значения (с абсолютным минимумом 0.0001 в шкале envelope). Это приближение обработанной кривой, а не обещание сохранить произвольный Bezier побитово. Исходный chunk сохраняется для точного Restore. При отсутствии envelope создаётся только VOLENV нужного take по GUID; вложенные FX/source и другие takes не меняются. Повторный Apply не перемножает прошлое ослабление. Изменение огибающей пользователем выявляется проверкой состояния.
- Ослабление широкополосное — автоматизация громкости айтема в найденных местах. Частотный срез управляет только детектором. Пересекающиеся запросы дыхания/сибилянтов берут максимум, не сумму. Порог относится к исходному сигналу, а не постфейдерной громкости. Сигнатуры [envelope API](https://www.reaper.fm/sdk/reascript/reascripthelp.html#Envelope_Evaluate) сверены со справкой.
- Для отказов после Glue исправлена чрезмерно строгая проверка длины: допуск два сэмпла источника вместо 1 microsecond. Больший выход по-прежнему отклоняется, с точной диагностикой. Пользовательские отказы до этого не содержали длин источника, поэтому округление пока является обоснованной гипотезой, а не доказанной причиной всех случаев.

Дополнительные автономные проверки: 101 значение Amount, подавление чередующегося дрожания, фактический FFT тона/яркого шума/тихого шумового события/тишины; cutoff выше прежних 8 kHz, исключение кандидата; адресация первого/среднего/последнего take и сохранение вложенного VOLENV в FX; умножение исходной автоматизации, координаты при rate 1.25 и source offset; повторный Apply, смена Amount, ноль с независимой очисткой, удаление созданной envelope при Restore, отказ вставки с откатом, запрет перезаписи ручной правки; частично-сэмпловый Glue и настоящий выход за источник. UI-модель проверяет секции, glow, событие отпускания Amount и правый клик. Синтаксис всех 15 Lua-модулей проверен. Новые детекторы, применение огибающей и внешний вид в настоящем REAPER ещё предстоит проверить пользователю; агент хост не запускал.

### Встроенный EEL

[Документация ReaImGui Function](https://cfillion.ca/reaper_imgui_doc.html#Function_Execute) прямо допускает самостоятельный `Function_Execute` для DSP. `CreateFunctionFromEEL` доступен с API 0.9; `Function_SetValue_Array` / `Function_GetValue_Array` переносят native arrays в RAM VM по адресу переменной. Код [реализации Function](https://github.com/cfillion/reaimgui/blob/master/src/function.cpp) подтверждает синхронный вызов `NSEEL_code_execute` и копирование double-массивов. Это не фоновый поток и не произвольный доступ к ReaScript API из EEL.

Пример в пользовательском `mrtnz subtitle editor old ver.lua` использует EEL как InputText callback и `Attach(ctx, function)` для времени жизни. Здесь используется самостоятельное исполнение: Lua читает аудио и вызывает native FFT; EEL считает взвешенную мощность 32 частотных полос. Кэшированные native arrays передаются блоками до 1024 кадров (максимум 32768 входных чисел). Одна VM и фиксированные адреса input/output/weights; несколько сотен KiB RAM, не весь PCM в VM. Пороговая логика, области, сглаживание и композиция остаются Lua с кооперативными паузами. При глубине/пороге даже EEL повторно не вызывается, если cutoff прежний.

`eel.lua` создаёт функцию один раз, прикрепляет её к GUI-контексту и сравнивает маленький результат с Lua. При ошибке компиляции/API/копирования переключается на Lua; причина доступна в отчёте. Нет gmem, EEL-экшена, сокета, вспомогательного процесса или дополнительной зависимости пользователя. Общие [EEL math](https://www.reaper.fm/sdk/js/basiccode.php#js_basicfunc) достаточны; перечисленные track-group/time-map/image-memory API к этому вычислительному циклу не относятся.

### Проверка без REAPER

В рабочем каталоге агента, вне папки продукта, собран отдельный C-хост исходников [Cockos WDL NSEEL](https://github.com/justinfrankel/WDL/tree/main/WDL/eel2) с `EEL_TARGET_PORTABLE`. Реальный парсер и VM выполнили именно kernel из `eel.lua`, с копированием массивов и постоянными адресами. Проверены 2055 кадров (два полных блока и остаток), cutoff 2/6.5/14 kHz, совпадение конечных curves с Lua с допуском 1e-9, исполнение через coroutine/main-loop bridge, fallback при отсутствии API. Это проверка семантики EEL; Windows x64 JIT/ReaImGui внутри настоящего REAPER здесь не запускался и его ускорение не измерялось.

Офлайн API-модель дополнительно проверяет самостоятельный захват без reference, диапазон из project time с offset/rate, сохранение произвольных curved markers, Apply без накопления, два слоя, удаление одного слоя, полное восстановление исходной envelope, Undo/Redo, ручные изменения, отмену устаревшего preview, неизменность feature-cache при amount и 150 событий ползунка без сохранений до финальной единственной записи. Обнаружено и исправлено накопление ослабления на feather-краях при повторном Apply. Модель GUI проходит все три вкладки, пустое/готовое/занятое состояния и баланс scopes. Реальный внешний вид и звук новой версии не объявляются проверенными.

На искусственном кэше **120000 кадров / 20 минут**, Lua 5.4 через Lupa, старый синхронный build занял около 416 ms CPU; новый полный холодный build без дробления около 445 ms. Сам по себе рефактор не даёт ускорения холодного Lua-расчёта. Новый пересчёт amount вместе с ограничением диапазона/композицией занял около 395 ms CPU, распределённых на 93 шага; самый длинный измеренный шаг 14 ms. При смене cutoff — около 651 ms на 158 шагов, максимум 7 ms. Непрерывный длинный шум также отдаёт управление (максимум 7 ms в этом прогоне). Это конечные измерения одного офлайн стенда, не real-time гарантия и не сравнение EEL JIT с Lua. Полное elapsed-время в REAPER зависит от defer/отрисовки. Отчёт теперь показывает backend, elapsed preview, число шагов и максимум шага для проверки у пользователя.


## 0.5.0 — 2026-09-30

Release previously used exp(-hop/release) on attenuation in dB, dropping to zero only below 0.01 dB. At a 20 ms time constant an 18 dB dip persisted for about 150 ms. The new finite linear ramps reach zero at the requested duration on the 10 ms analysis grid. Zero pre-open/release adds no synthetic tail. Continuous detector activity still holds attenuation; the FFT window also blurs event edges. Independent layer composition uses the stronger of de-ess and breath cuts, not their sum.

Cleanup now skips matching-only MFCC/spectral-normalization/chroma/delta work. Native FFT arrays use bulk copy/table transfers instead of per-number userdata indexing. REAPER cached peaks supply the immediate waveform, independently of the accessor analysis. Source peaks do not become detector inputs. The detector display has a separate -60..0 dBFS axis for high-frequency power; it is not calibrated against the auto-scaled waveform or post-FX audio.

The supplied EEL script rereads selected audio in RebuildVolEnvelope after control release. ExtState remembers per-take controls, not analyzed audio. Its native sample loop is a 2nd-order Butterworth high-pass, absolute-value follower (fixed 40 ms release) and compressor. Temporary playrate/length changes, SWS envelope manipulation and summed stereo were not copied. The supplied Lua waveform was used as a visual reference: symmetric outline plus translucent fill. Its arbitrary amplitude scale and envelope coordinate code were not reused.

Align now caches explicit reference/dub groups and draws all lanes. Analyze applies usable matches; control release updates the group. Strength blends the cached map, density/limits/smoothing rebuild from the cached path, and profile/search rematch cached features without FFT or rereads. Failed rematches discard stale correspondences. Low-confidence matches remain excluded. Breaths returns as the former unvoiced-noise heuristic with shared audio cache and an independent editable layer.

Offline validation: finite 20/0 ms release; cleanup-only/full DSP detector parity; bulk native-array API boundary; real WDL EEL VM and Lua equivalence; independent breath/de-ess apply/removal; baseline-envelope preservation; no drag writes; one transaction on release; A/B/A item and group recall; no matching/reading for marker-density changes; feature-only search rematching; Restore/reapply; Undo/Redo; failed-write rollback; new-item peaks without writes; three-tab/narrow-window UI calls and balanced scopes. The earlier real DSP/DTW synthetic tests retain their landmark errors and segment limits. Tests remain outside this product folder.

Synthetic 18 s / 180 s cached data: approximately 4 / 47 ms detector+scope+regions CPU, 3 / 34 ms envelope preparation. This excludes initial audio analysis, native writes and defer/drawing latency. Native REAPER and its GUI were not launched or controlled during this revision. Sound, peak coordinates under native take modes, visual control alignment and actual wall-clock responsiveness still need user testing.
